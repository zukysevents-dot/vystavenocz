# Web → mobil: parita pro první ostré vydání

Datum auditu: **2026-08-04**. Zdroje pravdy: `vystavenocz` `src/router/index.ts` (webové routy),
`vystaveno-mobile` `core/navigation/Navigator.kt` + `NavigationCatalog.kt` (mobilní obrazovky),
`vystaveno-api` `origin/main` @ `3d4d5a2` (kontrakty, `Permissions.cs`, `RolePermissions.cs`,
`ProductModules.ForPermission`).

Sesterské dokumenty: [`vystaveno-mobile/docs/MOBILE_RELEASE_READINESS.md`](../../../vystaveno-mobile/docs/MOBILE_RELEASE_READINESS.md),
`MOBILE_PERSONA_TEST_MATRIX.md`, `MOBILE_STORE_SUBMISSION_CHECKLIST.md`.

## Jak číst stavy

| Stav                    | Význam                                                                                                               |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `hotovo v mobilu`       | Celý průchod (list → detail → zápis → validace → stavové akce → chyby) je na mobilu a jede proti reálnému kontraktu. |
| `částečné`              | Jádro je na mobilu, ale vědomě užší rozsah; rozdíl je v poznámce.                                                    |
| `chybí`                 | Web to má, backend to má, mobil ne. Žádný takový řádek v této vlně nezůstal jako blokující — viz §3.                 |
| `web-only`              | Vědomě jen web (nevhodné pro telefon, nebo by šlo o klientskou fabrikaci dat).                                       |
| `public web`            | Veřejná stránka pro zákazníky/hosty, ne nástroj pro firmu.                                                           |
| `blocked backend`       | Chybí serverový kontrakt; mobil to nesmí předstírat.                                                                 |
| `není vhodné pro mobil` | Šlo by to, ale na telefonu by to bylo horší než na webu, a to měřitelně.                                             |

**Pravidlo, které tenhle audit používá:** existence položky v navigaci ani prázdný seznam se
nepočítají jako parita. Řádek je `hotovo v mobilu`, jen když prošel průchodem list / detail /
vytvoření / editace / validace / hledání / filtry / stavové akce / přílohy / loading / empty /
error / retry / role / modul / tarif / tenant izolace — a to, co z toho dává smysl, je ověřené
testem nebo živým voláním API.

## 10. Placení — proč mobil neprodává

`/app/predplatne` na webu vede k obchodnímu rozhodnutí o tarifu. Mobilní `SubscriptionScreen`
ukazuje **stejná data ze stejného endpointu**, ale nemá tlačítko k nákupu, odkaz na webovou
pokladnu ani uplatnění akvizičního kódu.

Důvod je store policy, ne lenost: prodej digitálního obsahu uvnitř iOS aplikace spadá pod
App Store Review Guideline 3.1.1 (In-App Purchase) a Google Play Payments policy. Odemknutí
placeného modulu kódem získaným mimo aplikaci je stejná kategorie. Dokud pro mobil neexistuje
schválený platební tok, je jediná varianta, která nezvyšuje riziko zamítnutí, neprodávat.

Owner/Admin proto vidí **bezpečný upsell**: co má v ceně, co nemá, a větu, že rozsah tarifu se
upravuje ve webové aplikaci. Ostatní role vidí totéž bez nabídky změny — `plan.canManageSubscription`
posílá server, klient si ho neodvozuje.

## 11. Modul + role + tarif: jedno pravidlo na obou klientech

```text
aktivní firma + membership + role + aktivní modul + entitlement/tarif = dostupná funkce
```

Na mobilu to vynucuje `ScreenAccess.evaluate()` (route-level, ne jen skrytý tab):
`NavigationCatalog` → `ModuleGates` ∧ `EntitlementGates` ∧ `RoleGates`.

V této vlně se srovnaly dvě místa, kde mobil gatoval **jen modulem** a ne tarifem — rozcestník
„Více“ (`ScreenRegistry.has`) a plovoucí tlačítko „+“ (`AppShell.shellFab`). Firma bez nároku tak
mohla vidět řádek nebo „+“, které route gate vzápětí zavřel upsell obrazovkou. Teď obě používají
`modul ∧ nárok`, stejně jako web.

Snapshot se obnovuje po loginu, po refreshi tokenu, po přepnutí firmy a **po návratu z pozadí**
(Android `MainActivity.onResume`, iOS `UIApplicationDidBecomeActiveNotification` — to druhé v této
vlně přibylo, iOS ho do teď nedělal).
